# Offline read-only journey viewer

Review dates, manual revisit conditions and acknowledgment timestamps are omitted. Use complete native JSON or Markdown to retain [revisit reminders](revisit-reminders.md).

Open **Export maps**, choose the exact saved nodes under **Offline read-only viewer**, and optionally select each node's saved answer and research. Everything starts unchecked. Choose **Preview included content**, review the complete structured text, then **Download previewed offline viewer**. Changing any selection clears the preview. Saved changes or journey switches require reopening the dialog and previewing again. Draft answers stay separate and are never included.

The download is one `exploration-viewer.html` file. Open it in Brave to search and read without an account, Copilot, the plugin server or a network connection. Use the node list, parent/child links, Previous and Next buttons. Native controls support keyboard navigation; Escape clears the search. The list stacks above the detail on narrow screens. JavaScript must be enabled for navigation. The viewer cannot edit, run AI, refresh research or save changes back to Explorer. Explorer can report a requested download, but cannot confirm the browser saved it.

Only exact selected nodes are exported. Parent links exist only when the immediate parent is selected; disconnected selections become separate roots. Excluded ancestors, their titles and global guidance are absent from the entire file. Folding and focus do not choose export scope. Generated node/source/claim IDs replace original identifiers; the document title and filename are fixed. Roles, categories, original Unicode text, answer states and needs-review flags are preserved. States describe user intent, not verification; no importance rank exists in current saved data.

Selected research includes recorded summary, compared options with pros/cons/details, proposed answers, recommendation, uncertainty, consulted sources and available structured claims with supporting model paraphrases and limitations. These remain **AI suggestions and interpretations**, separate from saved user answers. Imported read metadata is labeled imported, recorded reads do not establish truth, and legacy claim support/read provenance/retrieval time remain unknown. Research settings, generation rationale, follow-up exchanges and live helper state are omitted. Source URLs must be credential-free HTTP(S); links open only on deliberate activation, with opener and referrer protection. Opening one leaves offline operation and may use the network.

The dedicated field allowlist excludes structured local paths, live endpoints/tokens, credentials, drafts, private references, project captures, accepted briefs/handoffs, history and other metadata. **It is not text redaction.** Private names, copied paths, secrets or sensitive URLs that you put into selected content remain in the shared file. Review the whole preview before sharing; hiding a node in the viewer is not a privacy boundary.

Exports reject more than **500 selected nodes**, **1 MiB of projected UTF-8 JSON**, or **4 MiB of final HTML**. They never silently truncate selected content. Research keeps existing caps: 15 sources, 12 claims, three source references per claim, four options, six pros/cons each and eight details per option. Select fewer nodes or omit answers/research if a limit is reached. Wide/deep selections use a flat list and detail view, avoiding recursive graph layout. Unlike visual map formats, this viewer does not normalize XML-invalid controls or line endings; the embedded JSON round-trips original text, while browser glyph display can differ.

Implementation uses fresh validated saved bytes under the controller's serialization queue, with journey/revision/file identity checks before and after the read. A SHA-256 preview proof binds canonical original node selections and inclusion flags, journey/revision and the complete projection. It is freshness evidence, not a secret authorization token. The proof and original identities never enter the file. Live UI generations reject late responses after selection changes, closure or observed saved-state changes.

The file embeds fixed trusted JavaScript and CSS, with exact hashes in an early restrictive CSP. HTML-sensitive JSON characters and script terminators are escaped; user and AI text enters the DOM through `textContent`. No external scripts, fonts, styles, images or automatic requests are used. Hash input normalizes trusted code line endings for Windows checkouts. The design follows [CSP meta delivery](https://www.w3.org/TR/CSP3/#meta-element) and [HTML script content restrictions](https://html.spec.whatwg.org/multipage/scripting.html#restrictions-for-contents-of-script-elements). Unsupported meta directives such as `frame-ancestors` and `sandbox` are not claimed.

Automated checks execute the standalone file with networking denied in jsdom, inspect exact CSP hashes, safe hostile text, selected/excluded data, navigation, search, freshness and size limits. These checks do **not** prove browser CSP enforcement, visual layout or an actual saved download. Owner-only manual checks remain: native dialog and keyboard focus at narrow width, download/save/open in Brave, CSP behavior, Unicode/font appearance, long content scrolling, source-link activation and reading with networking unavailable. No browser or desktop automation is used.
