# Synthetic performance baseline

Run `npm run benchmark` from the repository root. The command writes `.perf-baseline/baseline.json` and `.perf-baseline/baseline.md`; the directory is ignored by git. It uses no user map or model provider. Fixtures are generated afresh with fixed IDs, timestamps, topology, populated answers and reasoning research, pinned user guidance, answer states, direction nodes, and an accepted reviewed brief. Each fixture passes `validateDocument`. The near-9 MiB case is approximately 60 KiB below the saved native limit. No large fixture file is committed.

The fixed cases are 64, 640, 2,400 and 4,950 nodes in both deep and wide shapes, plus a 4,950-node near-9 MiB wide shape. For each phase there is one warmup and two measured samples, run sequentially. The report gives operation counts and elapsed median/min/max in milliseconds, plus Node/OS/CPU, version, commit, dirty state, byte counts and SHA-256 fixture fingerprints. A failed fixture or phase retains its bounded error, the runner continues, both reports are written, and the command exits nonzero. Fixture setup, reporting and teardown are outside each timed operation; temporary files and history are removed, and each jsdom window and its poll timer are closed, after every warmup/sample. No fixed timing assertion runs in `npm test`.

Phases call `validateDocument`, `prepareResearch`, `prepareBrief`, `prepareAnswerCheck`, `toMarkdown`, native JSON serialization, `branchView`, `layout`, `atomicWrite`, and `Explorer.save` with history. The DOM phases evaluate the shipped `web/app.mjs` in jsdom with synthetic state responses and fixed geometry, then call its `renderMap`, `renderWorkspace`, `renderOutline` and `poll` functions. Workspace rendering selects the first saved research node. The benchmark adds accessors to the evaluated script only; production files are not altered. The poll count is one synthetic state request per call. These are JavaScript/DOM mutation costs, not paint times or native interaction latency.

For future versions, compare the same phase on the same machine only after checking fixture fingerprints and benchmark procedure. A repeatable result above twice the baseline is an informational investigation target, not a test failure. A changed fixture or procedure starts a new series.

Owner-only native check: in an installed desktop session with a disposable synthetic map, type in an answer and move the caret, including IME composition; switch focus with the keyboard; expand and fold branches; pan and zoom the map; resize to a narrow side pane; then confirm focus remains visible and input feels responsive. Record the installed version and machine when reporting observations. The benchmark cannot establish those outcomes.

Version 0.1.36 retains all fourteen original phase names, fixture fingerprints, setup, warmups and sample counts. The same `renderOutline()` call now returns immediately while Outline is hidden; its zero rows describe avoided hidden work, not faster visible Outline construction. Existing map/workspace calls now update mounted content instead of reconstructing it. Reports keep new `steadyState` measurements separate: ten selected-workspace updates and ten hidden Outline calls, with created elements, added listeners, editor identity and editor removals. These extra counters have no task23 timing baseline and must not be mixed into the original phase comparison.

Same-node updates keep the actual answer form connected, including its textarea, voice controls, manual direction field and question-help disclosure. Named regions refresh when their displayed inputs change; map/library rows retain their identities. A different journey, selected node or node kind owns a new workspace. Removed nodes return focus to a surviving map control while their persisted drafts remain recoverable. Native IME, OS dictation, layout and paint still need the owner-only check above.

Version 0.1.37 keeps the same nine fixtures and fourteen original measurement phases. Initial Fit still mounts the full visible layout, so the original `renderMap` phase measures that full-map case; selecting the research workspace permits culling in the original `poll` phase. New `viewInteractions.panZoom` measurements are separate: ten pan/zoom pairs at the selected research workspace, with positioned/mounted node and edge counts, geometry replacements and editor identity. They have no earlier timing counterpart. Zoom alternates between 90% and 100%, where editor dimensions remain stable; larger zooms that change editor dimensions correctly rebuild geometry.

The renderer retains one active geometry snapshot, uses a 96-screen-pixel overscan converted into world coordinates, and preserves any cubic connector whose conservative control-point bounds intersect it. This can retain some offscreen curves. It never treats offscreen endpoints as proof that an edge is invisible. Full logical content remains available to Outline, saved exports, history and context. Native appearance, pointer responsiveness, focus visibility while panning and narrow-pane behavior remain owner-only checks.
