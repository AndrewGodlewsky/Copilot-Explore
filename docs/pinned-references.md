# Pinned question references

In any ordinary question workspace, **Pin this question as a reference** adds its saved node ID to the optional **References** disclosure. At most three unique ordinary questions can be pinned per journey. The rows display the current committed source question, saved answer, answer state and needs-review flag. Long answers get a short preview and an accessible full-text disclosure. Empty answers are labeled as having no saved answer. Root ideas and user direction seeds cannot be newly pinned as answer references.

**Go to source** uses ordinary map selection, including branch reveal and focus exit, and cancels voice input. The current editor's unsent draft remains local. **Remove reference** only removes the pin and returns focus to the disclosure summary. Merely opening the disclosure neither selects a node nor changes folds or model context. If a history restore or import removes a source or changes it to a structural node, its ID remains a removable **Source unavailable** row. Restoring the same ordinary question ID makes the row available again.

References are local view metadata, separate from document JSON, history, drafts and navigation settings. Portable JSON and Markdown exports, native `get_exploration`, library summaries, question generation and research do not contain the pin list. A library journey uses its stable entry key, so divergent entries sharing a document ID stay separate. Direct-file use hashes the canonical file path and document ID, matching draft/history identity.

Explorer stores one file per journey under its owned data root at `references/<sha256-journey-key>.json`. The exact version-1 record is `{ "version": 1, "revision": 0, "nodeIds": [] }` on an empty journey, with no unknown keys. IDs are unique nonempty, trimmed strings of at most 100 JavaScript characters; revision is a nonnegative safe integer. Each file is limited to **4096 bytes**, and the private `POST api/references` JSON body to **1024 bytes**. Files contain no answers, prompts, paths or host IDs. Atomic replacement and an exclusive lock protect writes. Linked, nonregular, oversized or corrupt records are preserved and shown as an error with a safe empty fallback until repaired; writes remain blocked.

`GET api/references?journey=<active-journey>` returns `{journey,version,revision,nodeIds}` and may add `error` for unreadable storage. `POST api/references` accepts exactly `{journey,revision,nodeIds}` and returns the saved record. Both validate the active journey identity. POST requires the instance token, loopback Host, exact Origin and `X-Explorer-Client: 1`; newly added IDs must be ordinary questions in the active saved map. An unchanged save checks the expected revision and returns without writing or incrementing it. A conflicting writer is rejected without replacing its pins. The UI keeps the user's proposed choice and requires **Refresh & retry references** to read the latest revision and apply it. A separate canvas's document edits still require Explorer's normal explicit journey refresh; reference reads never silently replace the document or an unsent draft.
