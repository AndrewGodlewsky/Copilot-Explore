# Selected project files

In **Challenge decisions**, enter relative paths and choose **Read / refresh selected files**. Review the exact excerpts and model input, then choose **Start reviewed challenge**. Selection starts empty each time. Saved answers are still required: files alone cannot start a challenge. File instructions are quoted untrusted data; they cannot grant permissions, select more files or become user decisions or verified evidence.

Challenge Review file selection is limited to its owned helper with zero initialized tools. Its reviewed excerpts go to the selected eligible Copilot model when the challenge starts. They are excluded from attached-session question generation, web research/follow-ups, cleanup, question help, ordinary answer checks, decision briefs, implementation handoffs, native map context, saved journeys, history, exports and diagnostics. Its approval cannot authorize another operation. The attached chat retains its own host-controlled permissions and conversation. No public-search disclosure enforcement is claimed.

## Project-aware question scope

**Settings → Use project context** provides a separate, default-off workflow for project-aware questions. **Find candidate files** explicitly discovers metadata for conventional documentation, supported manifests and source entry points. It shows relative names, sizes, reasons, skipped entries and partial coverage before source contents are read. Selection starts empty. Select checkboxes, remove selections, or add relative paths manually. Up to ten exact file or folder exclusions apply alongside Git ignore rules and default exclusions; folder exclusions end in `/`, without glob patterns.

**Review scope** checks regular-file names, sizes, canonical path/ancestor identities, ignore policy and count/byte limits. **Enable reviewed scope** consumes a one-use ten-minute token, still without source-content reads. A separate **Read reviewed files** action consumes another one-use ten-minute token. It rechecks the complete approved selection before reading any source, checks policy again afterward, and returns local expandable excerpts with full-file and excerpt SHA-256 hashes, included/total bytes, truncation and capture time. Replaying a read cannot trigger another read. Status can recover an already captured receipt without rereading contents. Changed metadata, roots or ignore policy discard the capture; review and explicitly read again to replace it.

Active status says **Scope ready; project brief required** until a brief is approved. Discovery and local reads (#112) do not change generated questions or call a model. The correctable brief workflow below implements #113; project-aware generation (#114) follows separately. Ordinary questions continue through the attached chat without these files. Web research, exports, arbitrary repository code and other helpers gain no permission from this scope.

Scope and captures are held only in the current controller, outside map snapshots, history, native callbacks, exports and diagnostics. The absolute root and excerpts appear only in the local scope dialog. Root and selected-file metadata are checked on review/enable/status; active or uncertain scope is checked through existing browser polling, no more often than every ten seconds while the dialog is closed. Contents are never refreshed implicitly. Turning off, changing journeys, importing, changing page clients or closing the canvas clears scope and captures. Page suspension requests disabling best-effort; if delivery fails, a new client's status clears it before further actions. Editing scope or closing during pending approval/read also requests disabling it. Failed requests hide read tokens and excerpts, show uncertain status, keep Refresh and Turn off available, and continue reconciliation while the dialog is closed. Returning from suspension reconciles with a new client. A completed capture stays available when the dialog is merely hidden. Last-discovered metadata suggestions can remain while editing selections; they never authorize reads and are discarded on exclusion/root/journey/lifecycle changes. Neither scope approval nor a local read authorizes a model request.

Discovery bounds are depth 3, 40 visited directories, 300 examined entries including skips, 40 candidates, and a five-second cooperative budget checked between operations. Reads use the same cooperative time/cancellation boundary. An already pending OS filesystem call cannot be forcibly stopped; cancellation prevents subsequent work and late capture installation. Enumeration is bounded before sorting, so partial results are not an exhaustive ranking; narrower exclusions or manual paths can help. Generated/vendor directories, lockfiles, hidden/secret-name paths, unsupported extensions, links and nested Git repositories are skipped. Disappearing or inaccessible entries are reported without exposing contents. Binary content disguised under a supported extension is rejected during the explicit read.

Discovery and project-question reads require Git and a local repository. Bounded `git check-ignore --no-index` checks apply even to tracked ignored files and manually added paths. Git subprocesses have time/output limits, no shell, no fsmonitor/pager/lazy fetch/optional locks, and no inherited `GIT_*` overrides. Unavailable or invalid policy fails closed for discovery/reads; ordinary exploration still works. These read-only policy checks do not execute project code, install dependencies, load ambient instructions or retrieve network content. Challenge Review keeps its separate explicit-selection contract.

## Reviewed project brief

After reading the reviewed files, choose **Review brief request**. Expand **Exact request inputs** to inspect the literal instructions, captured excerpts, saved user corrections and byte count. Only **Generate brief** consumes this one-use ten-minute review token and starts the owned isolated helper. It uses the selected eligible Copilot chat model with matching account checks, no tools, no ambient instructions/skills, cancellation and content-free retained usage receipts. It does not use the dedicated Research model preference. Model work can incur normal usage and is not offline.

The result covers purpose, architecture, stack, conventions and constraints. Each section has up to five generated claims, with explicit unknowns where evidence is missing. Labels distinguish **File-backed claim**, **Inference**, **Unknown** and **User assertion**. File-backed claims require a captured source ID and a literal quote within that excerpt. Expand evidence to inspect the relative file name, full-file/excerpt hashes and supporting quote. Validation checks provenance and literal presence, not the truth of the model's interpretation. All content renders as text.

Edit individual claims, mark removals, or add assertions (500 UTF-16 code units each; up to 25 saved user assertions). Changed claims become user assertions with no file-evidence attribution. **Save changes** retains the draft in this canvas. **Approve brief** applies the current edits and explicitly approves that revision. An approved brief stays read-only until **Edit brief** confirms revocation. Ordinary questions remain unchanged in this version. **Review brief request** can generate a fresh draft from the capture and saved corrections; unsaved edits must first be saved or explicitly discarded.

Approval binds the canonical project, captured files and brief revision. Metadata/policy checks run during request review, start and status; full contents are verified before helper execution, after the result and before approval. These verification reads compare fingerprints and cannot refresh captured text. Scope changes, failed freshness checks, cancellation and stale results cannot install or approve a new draft. Corrections saved in the same canvas survive explicit recapture of the same canonical project as user assertions; a different project, journey, page client or canvas close clears them. Regeneration may propose a removed model claim again, so inspect the new result.

Polling preserves unsaved form text, caret and expanded evidence. If the scope or draft changes within the same project, unsaved text stays visible and read-only until **Discard local changes**; it is never silently applied to a different capture. A detected canonical project change clears saved corrections before recapture, including when scope is already off; the browser also clears the previous project's unsaved brief text. **Clear brief and saved corrections** explicitly clears server-held brief state. Closing the dialog cancels pending generation/review, while completed local drafts remain available in that canvas. An unconfirmed cancellation blocks approval of that run and retries through existing polling even with the dialog hidden; a late completed result is discarded when cancellation arrives. Suspension cancels best-effort and reconciles on return. There is no cross-reload draft persistence.

Briefs, supporting quotes, source metadata, corrections and approval are transient and excluded from maps, history, native map context, ordinary questions, exports and diagnostics. Exact requests and results can still appear in native SDK journals/provider retention (#41), and #42's network enforcement limitation remains. This feature claims neither external privacy guarantee nor live model usefulness. Synthetic fixtures cover the installed tool-free boundary; native rendering and real project usefulness remain manual acceptance.

## Selection and limits

The permitted root is the attached local session's current `rpc.metadata.snapshot().workingDirectory`, checked again during selection and freshness checks. `session.workspacePath` is an artifact directory and is never used as the project root. Missing/remote metadata disables file selection, while ordinary no-file challenges continue. Challenge Review does no recursive discovery. Only the explicit project-question discovery action walks the bounded tree described above; neither workflow indexes content, loads ambient instructions or writes project files.

| Bound | Limit |
| --- | --- |
| Selected regular files | 5 unique paths |
| Relative path | 240 UTF-16 code units, forward slashes |
| Source bytes | 64 KiB per file, 128 KiB selected total |
| UTF-8 prefix excerpt | 8 KiB per file, 32 KiB selected total |
| Actual instructions plus prompt | Existing 128 KiB UTF-8 ceiling |
| Review retention | One preview, 10-minute expiry |

Excerpts end on whole Unicode code points and show included/total byte counts. A complete file is decoded as strict UTF-8; binary/control content rejects. The source's full-file SHA-256 and excerpt SHA-256 are retained. Excerpt and aggregate limits reject excess selection rather than silently dropping a file. Normal optional saved-answer context can still be omitted by the existing budget; the exact preview reports those omissions.

Allowed extensions are md, txt, rst, adoc, json, yaml, yml, toml, xml, csv, tsv, js, mjs, cjs, jsx, ts, tsx, css, html, py, rb, go, rs, java, c, h, cpp, hpp, cs, swift, kt, sql, sh and ps1. Hidden paths, traversal, absolute/device/stream syntax, Windows reserved names, trailing dots/spaces and secret-name defaults reject before content reads. Secret defaults include env, auth/oauth, API keys, service accounts, keys, secrets, credentials, passwords, tokens, private and standard SSH identity names. This conservative filename filter cannot identify every secret inside otherwise permitted text; review what you select.

Links/junctions, hardlinks, nonregular files and unknown file identities reject. Ancestors/canonical paths and bigint file identities are checked before opening; handle identity is checked before content reads. Reads are length-bounded even if a file grows. Root, ancestors and file identity/stats are checked around reads. This is the repository's cooperative local-filesystem boundary: it detects observed replacement, but portable Node on Windows cannot atomically bind every ancestor against a malicious concurrent directory swap. UNC roots are unsupported.

## Freshness and retention

Public source fields are `{id,name,fingerprint,excerptFingerprint,bytes,excerptBytes,truncated,excerpt}`. IDs remain stable for the same path during explicit refresh within a review; names are relative. Internal root/file identity and absolute root remain private to the reader/request owner. No root/home path is added to portable data or diagnostics.

Ordinary context refresh and answer exclusions retain the reviewed file snapshot. Changed, missing, renamed or replaced sources/roots mark that snapshot stale; only explicit file refresh can replace its bytes and issue a new preview. Start and queued dispatch verify the full selected sources, and completion rechecks them. Later result polling uses bounded metadata/root/stat checks without full content rereads. This detects ordinary edits and replacements; it is not a filesystem watcher or a claim to detect hostile metadata spoofing. The UI source disclosure shows the original reviewed excerpt, relative name, ID, full hash and observed freshness.

Browser sequence, client, journey and one-use review-token ownership reject stale replies and mismatched starts. Preview cancel/close, expiry, journey switch or canvas close discards selected preview content. A running/completed challenge owns its captured sources until cancellation, replacement, journey switch or canvas close; hiding the result dialog alone retains that transient result. Panel reload requests cancellation best-effort; if delivery fails, captures may remain in the canvas controller until replacement, successful cancellation or canvas close. Stale results stop exposing findings. A running helper may retain already captured strings until it actually stops. Failure to reconcile native helper usage can preserve a recovery journal under the existing helper policy.

Explorer does not persist these excerpts or references in its map/exports/diagnostics or reuse them in later operations. **Native SDK helper journals/logs may retain prompts/results.** Tool-free does not mean offline, and strict native-log privacy remains unresolved (#41). Full network transport enforcement (#42) also remains unresolved. This feature does not claim either guarantee.

Local tests cover actual read boundaries, traversal/links/encoding/size, freshness, HTTP/UI selection and source canaries. Installed local fixtures verify metadata working-root selection and exact zero-tool helper strings without a paid provider or existing session. Native narrow-pane/keyboard rendering and live model usefulness remain owner checks.
