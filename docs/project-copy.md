# Save a reviewed project copy

In a Personal journey, choose **File → Save a project copy**. Choose a repository-relative folder and whether to include saved question research. Preview shows the destination and complete exact shared JSON. Confirm saves or verifies that copy; the personal journey remains open until you choose **Continue in project copy**. Save or cancel any active generation first.

This copies only validated committed document content: questions, answers and answer states, guidance, constraints, supported node metadata, and accepted briefs/handoffs. Research selection controls node research, including its evidence. Accepted artifacts retain their own historical text and evidence independently; inspect the entire preview. Explorer does not promise automatic secret detection. Unsaved answers are private drafts and do not appear in the copy.

The original personal file, drafts, private visual references, local history, attachment bindings, usage receipts and selected project excerpts remain private and unchanged. Continuing flushes private drafts to their original scope before opening the copy. It does not transfer drafts. No AI request, Git commit or network publication occurs. Teammates receive the file only when you share it through your normal Git workflow. They can open it through the [project library](project-library.md).

The copy has a distinct identity and `copyOrigin: {kind: "personal-copy", sourceId, sourceDigest}`. The digest describes the canonical committed source before optional research omission; it excludes the local revision and carries no local path or session identity. Node IDs and historical source references are preserved. Accepted artifacts remain historical, and their original identity fingerprints make them stale in the new journey; no historical verification is silently rewritten. Old clients that do not understand lineage reject editing this shared file. Use a current Explorer client.

Ordinary copies derive their identity from source content, research selection and destination folder (case-folded on Windows). Distinct folders therefore receive independent journey IDs and private state. Retrying confirmation, or preparing another ordinary preview after a lost response, recognizes the identical existing copy in the chosen folder. Existing files are never overwritten. Divergent copies require opening the existing journey to reconcile, or explicitly selecting **Create an additional independent copy**. That option creates a fresh identity per preview; retries of that same preview reuse it. After closing/restarting or a 15-minute expiry, inspect the Project library before requesting another additional copy. There is no automatic continuation across sessions.

Preview captures source bytes, active checkout authority and existing destination ancestors without creating project folders. Confirmation rechecks them under the personal document lock and uses the existing project creation locks and atomic writer. Stale sources, changed destination bytes, unsupported content and unsafe paths fail closed. A failed write leaves originals intact; identical private creation history allows retry of the same prepared copy. These are cooperative local safeguards, not protection against a hostile process replacing paths between system calls. Nothing claims cross-machine locking.

Automated coverage includes source/destination changes, retries, injected write failure, Unicode, research provenance, historical artifacts, clean-clone reopening, strict HTTP origin handling, and a DOM workflow that preserves personal drafts. Owner native narrow-pane, visual and keyboard checks remain pending; no browser/desktop automation is used.
