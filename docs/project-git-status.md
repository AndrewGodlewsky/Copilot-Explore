# Save and Git status

In a Project journey, open **Journey details → Save and Git status**, then **Refresh local Git status**. This is a local observation of the selected file, separate from private answer drafts. Refresh preserves editor text, selection, focus and pending model requests. It does not save answers or change Git state.

The panel distinguishes an exact saved base from a changed/unavailable/missing file or checkout. It reports untracked and ignored paths, staged and unstaged changes (including both at once), conflicts, and a file committed in the local HEAD. A clean selected file says nothing about other files. Private drafts may be safely saved locally while still absent from the shared exploration file; commit answers explicitly before sharing them.

Branch and upstream counts describe the whole repository branch. Detached HEAD, branches without commits, missing upstream and unavailable comparisons remain explicit. Ahead/behind counts use the local refs Git currently knows. **Remote freshness is always unknown**: a zero/zero comparison does not establish that GitHub or a teammate has the same content. Use your Git workflow to fetch, review, commit and share. Explorer performs none of those operations here.

Each result displays its observation time. Refresh after external Git/file activity; a map revision or reconciliation notice marks an older observation as potentially stale. No status cache is written to the journey or user storage. Refresh uses a path-scoped Git porcelain query, literal arguments, a five-second command timeout, a 64 KiB output cap, disabled optional index writes and disabled filesystem-monitor hooks. Ambient Git environment overrides are removed. Physical checkout identity, metadata selection and selected-file identity/bytes are rechecked around the query; races and unavailable evidence produce an unknown result. Unexpected command details and absolute checkout paths are not displayed.

The implementation uses the installed Git executable and supports normal worktrees. It does not inspect arbitrary repository content, call network services, use Copilot inference, run shell interpolation, stage changes or automatically reconcile a changed file. Use **Review project changes** for the latter. These are cooperative observations rather than an atomic transaction across an externally changing repository.

An empty status response alone cannot establish a committed file: Explorer also requires the exact regular file in HEAD and the normal index with matching mode/object ID. Nested repositories/gitlinks and assume-unchanged/skip-worktree entries cannot satisfy that check. Effective content filters (including LFS) are refused before status because Git could execute their external commands. Submodule scanning and lazy object fetching are disabled. Git versions that cannot honor these switches report unavailable status. Changes to attributes/configuration by another process between checks remain outside the cooperative observation guarantee.

Local fixture tests cover saved/untracked, ignored, staged/unstaged, clean committed, missing, conflicted, rename, detached/unborn, divergent/no-upstream, literal paths, worktrees, bounded failures and source changes. DOM/HTTP tests retain connected drafts and pending work. The installed SDK fixture checks explicit status without inference. Owner native narrow-pane/keyboard verification remains pending; no browser/desktop automation was used.
