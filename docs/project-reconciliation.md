# Reconcile changes from Git or another writer

An open Project journey checks its displayed base on state refresh (at most once every five seconds) and before project operations. Checks bind the physical checkout, current Git branch/HEAD, canonical parent identities, regular-file identity and exact content fingerprint. A branch switch, replacement, deletion, conflict marker, malformed file or unavailable checkout stops editing. Matching revision numbers alone never authorize a save.

The notice keeps the displayed map and draft editors available. Choose **Review project changes** in the notice or File menu. Refresh reads the current repository file into an exact JSON preview. **Reload reviewed file** explicitly adopts that captured content and current checkout authority without rewriting the repository file. A second change after preview rejects reload. A different physical checkout or journey identity must be opened separately from the Project library; it is never silently treated as the original journey.

**Preserve displayed version** stores the current displayed committed base privately, including when the original file is missing, renamed or conflicted. File → Recovery can inspect it and offer the existing separate-copy workflow. This preserved version does not include unsent drafts. Drafts remain in their original stable journey namespace; reload flushes editor changes before switching the committed base. Changed answers become explicit stale draft conflicts and removed-node drafts remain available for recovery. It does not automatically rebase, commit or discard draft text or answer state.

Detection invalidates owned helper work and candidate question acceptance. Late callbacks cannot change the map. Cancelling a queued question invalidates its Explorer request only; it does not stop the attached user's chat turn. No model request is replayed. Existing research, brief, handoff, history and question acceptance paths use the shared saved-source freshness boundary; future ADR operations must do the same.

Reload preserves existing private history folders. A new history namespace records the displayed base and incoming content using the same history intent/finalization protocol. An atomic `history-state.json` pointer selects the active namespace after the incoming bytes and checkout are rechecked. Interrupted finalization is resolved against that selected history on reopen. Invalid/uninitialized pointers fail closed. Local revisions advance when the shared content changes. No Git or repository file write is performed by reconciliation.

Private draft/reference/helper storage stays stable across these history changes. Recovery prioritizes the most recently preserved version (recorded in private `preserved-state.json`) and the active history before scanning other namespaces. It scans at most 32 history namespaces from a bounded 128-entry directory, with aggregate limits of 50 snapshots and 128 MiB. Duplicate snapshot hashes appear once. Partial results report omitted/unavailable records; all older namespaces remain protected. An invalid active-history pointer blocks editing but does not hide independently validated recovery snapshots. Retention cleans eligible snapshots only in the active history namespace and rejects a cleanup preview if the pointer changes. Use a current Explorer version to read the new private history selection; older installations do not understand it. Existing teammates can still open the shared file without these private records.

Safeguards are cooperative local checks and atomic private saves, not a distributed lock or protection against a hostile process replacing files between system calls. Fetching, pulling, switching branches and resolving semantic Git conflicts remain explicit user/Git operations. Unavailable or malformed files are preserved for that workflow.

Automated tests cover content/revision conflicts, same-byte replacements, branch changes, missing/renamed/invalid/different-identity files, stale previews, pointer interruption, prior checkpoints, owned-work cancellation, late callbacks and exact draft recovery. DOM/HTTP and the installed local SDK fixture exercise explicit reload without inference or rewriting incoming bytes. Owner native narrow-pane, visual and keyboard checks remain pending; browser/desktop automation is not used.
