# Compare research options

Open **Compare options** in a question's Research drawer. Saved detail labels provide criteria specific to that question. Exact labels and duplicate values are preserved; missing values say **Unknown**. Older results without details can use a custom criterion. Descriptions and pros/cons stay on the option cards.

Select criteria and set High, Normal or Low priorities, or add up to eight custom criteria of at most 160 UTF-16 code units each. Priorities reorder the saved rows without calling a model, calculating scores or changing a saved decision. Select one to eight distinct criteria for reconsideration. If more are selected, or labels differ only in case/spacing, the panel asks you to reduce the selection; it never silently drops criteria. Hiding a criterion preserves selected saved details and their existing draft actions.

**Reconsider recommendation** opens an inline review of the hypothetical priorities, every compared option, prior research and bounded current saved map context. Expand **Exact inputs** for the literal instructions/prompt, optional exclusions and omissions. The review names the selected or dedicated [Research model](research-model.md), the three-minute operation limit and zero tools. The model provider receives these inputs. There is **no new retrieval**, no project-file context and no newly verified evidence. Original Research and follow-up source permissions are unchanged.

The proposed comparison includes one explanation per selected criterion and option, reasoning/unknown/prior-claim labels, a suggested option or explicit no recommendation, changed and unchanged reasoning, and uncertainty. Prior-claim disclosures identify historical model assertions and their recorded evidence; they do not prove entailment or freshness. **Use revised comparison** makes it the current hypothetical comparison. **Keep current comparison** dismisses the proposal. Both leave saved research, its recommendation, all answer options and the answer draft intact. A failed or cancelled replacement preserves the accepted comparison.

Only one accepted comparison and one proposal are held privately per canvas, across node navigation. They are absent from saved maps, native snapshots, history and exports, and cleared on canvas close, journey switch or import. Local criteria reset on reload, journey switch or observed research replacement. Relevant saved-context changes mark retained comparisons historical irreversibly. Changed priorities invalidate an unused review and prevent adoption of its result even if changed back. A retained proposal after page reload is read-only until a new explicit reconsideration; it can still be dismissed. Saving a new answer remains a separate user action.

Tables stack with explicit option labels in narrow panes, retaining table roles and keyboard controls. Criteria edits, progress and result arrival preserve mounted answer and discussion editors. As with the rest of the research workspace, physical screen-reader/IME behavior and visible native Copilot rendering require separate acceptance; Brave checks do not establish those.

## Implementation and checks

Recorded [recommendation blockers](research-limitations.md) remain binding during tool-free reconsideration: the result may compare choices but must keep a null recommendation. Hypothetical priorities cannot establish missing evidence or resolve actual contradictory constraints. The user's own answer remains independent.

`research-comparison.mjs` validates exact criterion IDs/labels/priorities, packs complete mandatory options and prior evidence with the existing 131072-byte context limit, and rejects mandatory overflow. A result must contain the complete grid (at most 32 cells), known option/criterion/claim IDs, bounded explanations and a strict 65536-byte JSON payload. Legacy options receive request-local IDs bound to that full research snapshot. Structural checks cannot prove that a model explanation is true.

The existing single-use ten-minute Research review binds purpose, source/destination/scenario and model capture. An owned isolated helper verifies the account, eligible captured model and zero initialized tools before inference; ambient instructions/skills, plugins and MCP are disabled and permission requests denied. Cancellation stops only that helper, with normal release and usage reconciliation. `operation.json` records the verified model under `research-reconsideration`; usage is labeled **Explorer Research Reconsideration**. Adoption rechecks saved source/destination/scenario under the document lock without writing the document. Current research is required; a stale research record must be researched again first.

Focused contracts, controller/HTTP and DOM tests cover input/output bounds, stale/reused reviews, malformed/cancelled/late results, source and local-priority A-B-A, unknown support, Unicode, draft retention and explicit adoption. `npm run e2e:research` uses the installed SDK/runtime and anonymous local fixtures to exercise selected and dedicated models, exact reviewed input, zero tools/MCP retrieval, cancellation and receipts. Authorized Brave checks cover five viewport sizes, stacked comparisons and keyboard Use/Keep. No fixture invokes a paid provider or existing session; live research quality, #41 native-log privacy and #42 network enforcement remain separate.
