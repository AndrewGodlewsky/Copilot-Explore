# Review dates and manual revisit conditions

Open an ordinary question and use **Revisit this question** to save a review date, a condition, or both. Reminders belong to you and are independent of the saved answer, answer state and ancestor **Needs review** flag. The idea root and user direction nodes cannot have reminders. Older files have no inferred schedules.

Dates are real local-calendar `YYYY-MM-DD` values, from `0001-01-01` to `9999-12-31`. The same written day is displayed everywhere; it is never converted through UTC midnight. **Due today**, **Overdue** and **Upcoming** compare the date with the computer/browser's current local calendar. Traveling or changing the local time zone can change urgency, but never the saved date. Existing polling and return-to-page handling refresh urgency even when the saved revision is unchanged. No machine-clock change is required.

Conditions are exact user text, limited to 1,000 UTF-16 code units. A condition without a date must contain nonblank text. **Manual condition** means you must evaluate the statement yourself; Explorer does not detect whether it happened. No background world monitoring, AI requests, external notifications or calendar writes run for reminders.

**Acknowledge review** stores the server's actual timestamp and keeps the date and condition visible as **Acknowledged**. It records that you chose to review the reminder; it does not claim that the condition occurred, resolve a decision, change an answer or clear an ancestor review flag. **Reschedule and reactivate** explicitly saves your schedule with acknowledgment reset, even when you keep the same date/condition. **Clear reminder** removes the current reminder. All actual transitions are revision-checked saved edits with History; older schedules and acknowledgments remain available subject to normal history retention. Repeated acknowledgment, unchanged active save, and clearing an absent reminder check disk freshness without inventing revisions or events.

The question list's **Reminder status** filter supports any reminder, needs attention, overdue, due today, upcoming, manual condition and acknowledged. The Library offers the same filters, per-journey counts and earliest active date. **Needs attention** is a count of distinct reminders that are overdue, due today or have a manual condition. Status counts overlap: one reminder may be due today and have a manual condition. Library summaries omit condition text. **Revisit** opens the first matching question and reveals its map path; the question list provides the other matching sources. The **Archived journeys** checkbox exposes archived reminders explicitly. Opening one never unarchives the journey.

Reminder edits stay in the current canvas while you move among questions. Save them or choose **Use saved reminder** before switching journeys or restoring History. They are not durable answer drafts: reloading the canvas can lose unsaved reminder edits. A changed saved reminder leaves your edits intact and requires **Use saved reminder** or **Keep my reminder edits** before saving. Answer drafts and their editor stay separate. Acknowledgment and clearing require you to finish or discard reminder edits first.

Native JSON, imported copies and History preserve validated reminder metadata. Complete Markdown exports include the date, manual condition and acknowledgment; Markdown is a human-readable record, not an import format. JSON round trips preserve exact text. Existing helper source projections omit reminder metadata, so reminder-only edits neither transmit condition text nor invalidate unchanged captured answer/guidance sources. The separate native `get_exploration` snapshot remains a full document snapshot; this feature makes no tool-log privacy claim.

Mermaid, JSON Canvas, SVG, print/PDF and the offline HTML viewer deliberately omit reminder dates, conditions and acknowledgments through their existing field allowlists. Use the complete native/Markdown export when these are needed. A reminder edit still changes the saved revision, so an already captured portable-export request or offline preview must be refreshed. This is export freshness, distinct from unchanged model-source content.

Automated tests cover local dates/time zones/DST, invalid dates, no-op and stale-writer semantics, History/import/export, source projection freshness and real HTTP/jsdom editing/navigation. Native desktop layout, the platform date control, narrow-pane keyboard/scroll behavior and actual downloads remain manual owner checks; no browser/desktop automation is used.
