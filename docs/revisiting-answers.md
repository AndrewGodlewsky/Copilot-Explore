# Revisit this answer

Open an ordinary question, edit its proposed answer in the existing editor, then choose **Revisit this answer** in the Explore drawer or Commands. The chooser stays in the bottom drawer. It names the current journey/scenario and project path, when applicable, and summarizes recorded downstream impact.

- **Change and retain descendants** uses the existing answer-save flow. The consequence preview shows affected reasoning; confirmation retains those answers and marks them for review.
- **Explore an alternative scenario** opens the existing fork workflow with the proposed text and state. Review the copied context, save to the personal library, and explicitly open the scenario when ready. The original stays intact. Fork is unavailable in file-only previews without the installed library.
- **Change and restart below this question** uses the existing restart flow. Review exact removals, then explicitly confirm. A protected History checkpoint precedes the saved change. Outside affected reasoning survives for review. Nothing regenerates automatically.

Changing choices does not save or replace the editor. **Back to editing** or Escape exits the chooser and restores editor focus; another Escape closes the drawer. Child confirmation dialogs retain their own cancellation behavior. The existing direct restart and fork actions remain available.

The impact overview describes structural relationships, not predicted real-world damage or an exact deletion count. The selected domain workflow supplies the full consequence/copy preview and source fingerprint checks. A saved-context change or resumed page requires **Refresh choices** before continuing. Pending requests and staged questions show explicit instructions to finish/cancel or accept/dismiss first. Draft conflicts and manual direction/reminder drafts retain their existing resolution requirements.

If protected History capacity is full, remove an appropriate checkpoint through History before retrying restart. If storage is read-only or unavailable, restore access and retry using the retained draft; no chooser action bypasses the existing atomic save guards. Canceling a proof, a stale proof, or a failed write keeps the original and proposed text intact. After a successful ordinary save, the existing Save & continue behavior may select another unresolved question.

This is UI coordination only: answer, restart and scenario-fork commands remain the owners of mutation, history, source validation and helper isolation. No new generation command or SDK behavior was added. It does not merge scenarios or choose a preferred answer.
