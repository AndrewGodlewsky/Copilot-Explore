# Reviewed ADR scope selection

Goal: Select one focal decision and explicit supporting saved records, inspect the bounded input, and retain a source reference for later ADR work without generating an ADR or approving a decision.

Spec: GitHub #75, prerequisite #53 complete. Base: 0.1.90, 6b296bafc2d2914a989970169928e6ddaba81fb8.

Architecture: Reuse the implementation handoff's selected-record projection, brief source capture/freshness, ResearchReview token lifecycle and existing atomic controller saves. Add a small ADR scope module, one optional saved adrScope reference, and a dedicated UI dialog. No model calls, SDK changes, file writing into a project, templates or draft generation.

## Constraints and rulings

- One current saved scope per journey. Replacing it does not change existing artifacts or answers. Later ADR drafts must retain their own input captures and require a new review.
- The focal record is an ordinary question; unanswered, tentative and needs-review questions are valid. Explicit supporting questions/directions can be from any branch. Focal is included; ancestors and descendants are never silently included.
- All global guidance and constraints are mandatory and visible. Optional research includes only recorded sources/structured claims, preserving provenance and uncertainty. Private drafts, project captures, unselected records and synthesized artifacts are omitted.
- Select 1-100 unique records; all selected content is mandatory within the 128 KiB exact instruction/input budget. Reject overflow without truncation.
- Store source IDs, question/state/review metadata and fingerprints, selection, evidence/scenario fingerprints, coverage and timestamp. Do not duplicate answer/research text. Saved scope is a reusable reference, not permanent authorization to send it later.
- Scoped freshness tolerates unrelated saved edits. Preview acceptance additionally guards the full saved document after asynchronous policy/history work to prevent lost updates. Unavailable scenario policy means unknown freshness, never current.
- Validate personal/shared import and retain stale historical references. Older shared readers reject the unsupported field; older personal readers may drop it. No schema migration or dependency.
- Native browser/desktop checks remain pending owner; use HTTP/jsdom and local deterministic tests only.

## Review focus

- No unselected answers, private drafts, project excerpts or previous artifact content in exact preview or saved scope.
- Partial/review states and optional research cannot become accepted decisions by selecting/saving.
- Focal/selected/captured IDs agree; removed historical sources remain stale and cannot be rebound to unrelated nodes.
- Evidence, guidance and scenario changes invalidate the same projected material that was reviewed; canonical shared serialization does not falsely refresh or corrupt captures.
- Strict purpose, client sequence, expiry, cancellation, navigation and final async write guards prevent token reuse or lost corrections.
- UI selection/save/cancel/page suspension preserves connected drafts/caret and ignores detached controls or late responses.
