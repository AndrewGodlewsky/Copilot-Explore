# Issue #63 — explainable downstream decision impact

Approved #63 is the spec; implement after #62 publication, inline with TDD and one final independent review.

1. Pure saved-map analysis with bounded iterative traversal. Build an index once per current saved document, using tree parent→child edges and explicit prerequisite→dependent links. Report unique affected ordinary question IDs (never the source), state counts, review count and unverified assumption count. Keep tree-only exposure, explicit-only confirmed reachability, and mixed-path possible exposure distinct. Union traversal may contain cycles even when each source graph is acyclic, so visit once and exclude the source. Stable-ID ordering gives deterministic shortest reproducible paths. Store compact predecessors and construct a chosen path on demand; never materialize O(V²) path arrays for deep maps.
2. Impact bands: high if ≥20 unique affected questions or ≥5 confirmed dependents; medium if ≥5 unique affected or ≥1 confirmed; otherwise low. Show raw counts and threshold text. Bands describe recorded reasoning exposure, not code effort, truth or model confidence. Historical low/medium/high importance and reason stay unchanged and separately labeled. ADR associations explicitly unavailable until a supported association schema is delivered (#84); no fabricated zero count.
3. Add a reusable browser-safe pure module, re-export model entry points. Current UI computes one selected question on explicit opening of Impact in Question tools Context, not every node on every render. Cache/index tied to relevant saved content and bound the selected-result cache; changed content invalidates even at the same revision. Identical status-only snapshots preserve results, paging and DOM. Drafts, folds, viewport, focus and local selection do not enter computation. Small results UI includes band, state counts, relation counts, limitations, an affected-question selector with path detail and native navigation. Use saved question/state data only and plain text. Keep editor connected. Later issues #64/#65 consume the same analysis for map encodings/focus rather than duplicating calculations.
4. RED/GREEN fixtures for leaves, chains, wide/overlapping/mixed paths, reverse-to-tree cycles, all answer states and review, stable path selection, legacy maps and historical importance preservation. UI verifies fold/draft independence, recompute on saved state/link changes, navigating hidden/focused-out questions and retained drafts. Add focused benchmark using existing synthetic fixture approach, warmed multiple runs, environment metadata, near5k deep/wide plus up to10k cross-links. Report actual timings/operation bounds; no desktop/browser automation. Full test/check/package; no SDK fixture unless host wiring changes.
5. Document rules, limits, ADR unavailable state, benchmark evidence and manual native checks pending. Patch .78 after .77, release note, final independent review and material fix pass if needed. Fetch/integrate/push main, verify remote, comment and close #63; continue #64.

Ruling: mixed tree/dependency paths are possible exposure, never confirmed dependence; include them transparently so a branch leading into another confirmed link is not missed. Separate pure-relationship paths remain visible. Bands use total/confirmed counts only; answer-state and assumption/review counts give context without arbitrary certainty weights. Nodes/data are not modified by analysis.
Preflight: browser module import must be allowlisted by server/check and injected in both jsdom test and existing perf harness. Source invalidation follows saved document changes; poll cursor skips must not use draft state. Full paths are built only for inspected item to avoid quadratic deep-chain output.
